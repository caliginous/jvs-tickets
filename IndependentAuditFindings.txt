### 🚨 **WHAT I DISCOVERED THAT WAS MISSED:**

#### **Bug #3: Admin Payment Link Double Conversion (NEW CRITICAL FINDING)**

**Location:** `src/pages/api/admin/order/create-simple.ts` + `src/lib/stripe.ts`

**The Problem:**
1. Frontend sends ticket prices in **pounds** (e.g., 5.00)
2. Database category prices are in **pence** (e.g., 500)
3. Code mixes both formats without proper conversion:
   - Line 187: `ticketPrice = priceNum` (from frontend, in pounds)
   - Line 190: `ticketPrice = category?.price ?? 0` (from DB, in pence)
4. Both get passed to `createPaymentLink` as if they're the same unit
5. `createPaymentLink` does `unit_amount: ticket.price * 100` assuming pounds
6. **Result:** Category prices get multiplied by 100 TWICE (500 pence → 50000 pence = £500)

**Impact:** Admin-created payment links with category prices charge 100x the correct amount!

#### **Data Pattern Discovery:**
Database analysis revealed `discountAmount` field is being misused:
- Should store discount amounts in pence
- Actually stores refund amounts in pounds (due to Bug #2)
- Creates semantic confusion and data corruption
