COMPREHENSIVE MONETARY AMOUNT AUDIT PROMPT

CONTEXT & CRITICAL ISSUE:

You are auditing a ticketing system that suffered from severe monetary amount inconsistencies. The system had mixed storage formats where some amounts were stored in pence (minor currency units) and others in pounds (major currency units), causing incorrect displays, refunds, and payments.

CRITICAL EXAMPLES OF THE BUG:
- £5.00 tickets displayed as £0.05 
- £5.00 refund requests only refunded £0.05
- Stripe charged £5.00 correctly but database stored 5 pence instead of 500 pence
- Email confirmations showed £0.05 instead of £5.00

STANDARD ADOPTED: All amounts MUST be stored in pence (500 pence = £5.00) and converted to pounds only for display (500 ÷ 100 = £5.00).

================================================================================

COMPREHENSIVE AUDIT INSTRUCTIONS:

🗄️ 1. DATABASE STORAGE AUDIT

Check these tables and fields:
```sql
-- Order amounts (MUST be integers in pence)
SELECT id, finalTotal, originalTotal, discountAmount, refundAmount 
FROM Order 
WHERE finalTotal > 0 OR originalTotal > 0;

-- Ticket type prices (MUST be integers in pence)  
SELECT id, name, price, currency 
FROM EventTicketType;

-- Check for non-integer amounts (RED FLAG)
SELECT * FROM Order WHERE 
  (finalTotal IS NOT NULL AND finalTotal != FLOOR(finalTotal)) OR
  (originalTotal IS NOT NULL AND originalTotal != FLOOR(originalTotal));
```

VALIDATION CRITERIA:
- ✅ All amounts should be integers (pence don't have decimals)
- ✅ Reasonable ranges: 50-100000 pence (£0.50-£1000.00)
- ❌ RED FLAGS: Amounts like 5.00, 25.99 (likely stored as pounds)
- ❌ RED FLAGS: Amounts < 10 pence (£0.10) or > 1000000 pence (£10000)
